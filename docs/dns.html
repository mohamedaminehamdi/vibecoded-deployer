DNS: Route 53 and GoDaddy

Both providers end with the same CNAME. They differ in who validates the certificate.

Side by side#

Registrar versus DNS host

The choice is about where your domain's DNS records are hosted, not where it is registered. A domain registered at GoDaddy whose nameservers point at Route 53 should use route53. A Route 53 zone that nobody delegates to will never validate the certificate.

Route 53 flow#

  1. Prepare the zone

    Create a public hosted zone named exactly like domain_name in the same AWS account as your credentials, and make sure the domain's nameservers point to it.

  2. Run the deploy workflow with dns_provider = route53

    The workflow finds the zone with aws route53 list-hosted-zones-by-name, matching the name exactly, and stops with Could not find Route 53 hosted zone if there is none.

  3. Terraform validates the certificate

    Terraform requests the certificate, writes its validation record into the zone (TTL 60), waits until ACM issues it, and then creates the CloudFront distribution.

  4. The workflow writes the CNAME

    After the upload it upserts <subdomain>.<domain_name> as a CNAME to the CloudFront domain, TTL 600.

GoDaddy flow#

How this was derived

The steps below follow from reading the workflow and Terraform code: without a Route 53 zone, nothing creates the validation record or waits for the certificate, and CloudFront only accepts a certificate that has been issued. They have not been exercised end to end against a real account. If your first run behaves differently, please open an issue.

  1. Create API credentials

    Create a production API key and secret in GoDaddy's developer portal and store them as the repository secrets GODADDY_API_KEY and GODADDY_API_SECRET. GoDaddy may restrict API access depending on account type, so confirm yours has it.

  2. Run the deploy workflow with dns_provider = godaddy

    Terraform creates the S3 bucket and requests the certificate. Without a hosted zone it creates no validation record and does not wait. Creating the CloudFront distribution with a certificate that is not yet issued is expected to fail, so the Terraform apply step fails. That step is continue-on-error, so the job continues: it still builds and uploads your site and may end green.

  3. Add the validation record in GoDaddy

    Find the record's name and value in the ACM console (region us-east-1, your certificate, Domains). If your Terraform state recorded the outputs, you can also read them with terraform output -json certificate_validation_records after pointing a local backend.tf at the project's state (see terraform/backend.tf.example; this needs Terraform 1.10 or newer).

    Create it as a CNAME record in GoDaddy's DNS manager. Most DNS editors want the host without your domain suffix, so strip the trailing .<domain_name>. from the name.

    Wait until ACM shows the certificate as Issued.

  4. Run the workflow again with the same inputs

    The bucket exists but the distribution does not, so Terraform runs again. It reuses the certificate from state, creates the distribution, and the workflow then writes the CNAME through the GoDaddy API.

Wrong CNAME on the failed first run

If Terraform did not produce a CloudFront domain, the workflow falls back to the bucket's S3 website endpoint as the CNAME target. After the second run, the CNAME is replaced with the CloudFront domain. Until then the name serves the site over plain HTTP from S3 and the HTTPS certificate does not apply.

If you want to skip the manual step for good, move the domain's DNS hosting to Route 53 (change the nameservers at your registrar) and use the Route 53 flow.

Checking DNS#

dig +short my-site.example.com CNAME
dig +short _<token>.my-site.example.com CNAME   # certificate validation record

The site CNAME should point at a *.cloudfront.net name. With a TTL of 600 seconds, changes can take up to ten minutes to be seen by resolvers that cached the old answer.

DNS on teardown#

The destroy workflow attempts to delete the site CNAME in Route 53 (if it finds a zone named domain_name) and at GoDaddy (if GODADDY_API_KEY is set), regardless of which provider you used. Route 53 certificate validation records are removed by terraform destroy. A validation record you added by hand at GoDaddy is never removed; delete it yourself. See Redeploy and teardown.
