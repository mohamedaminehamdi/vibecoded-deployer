Quickstart

From a fresh fork to a live HTTPS site. Allow about ten minutes of your time, plus a few minutes of AWS waiting.

Before you start#

Prerequisites
You needWhy
An AWS account and an IAM user with access keysThe workflows sign in with AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY secrets. See AWS permissions.
A domain with DNS hosted in Route 53 or GoDaddyThe workflow creates the CNAME <subdomain>.<domain>. See DNS.
One GitHub account or organization that owns both this repository and your Lovable repositoryThe Lovable repository is checked out from <owner of this repo>/<repo_name>. A private Lovable repo also needs the optional ACCESS_GITHUB_TOKEN secret.
A Lovable repository that builds with npm ci and npm run buildCommit package-lock.json, keep a build script, and make sure the output lands in out/, build/ or dist/.
Terraform 1.3 or newer and AWS credentials on your machineOnly for the one-time state bucket bootstrap. The workflows install their own Terraform.

Costs

You pay AWS for what the workflow creates: S3 storage and requests, CloudFront data transfer, and Route 53 if you use it. ACM public certificates are free.

Steps#

  1. Get your own copy of the repository

    Fork mohamedaminehamdi/vibecoded-deployer (or clone it and push it to a new repository) into the GitHub account or organization that owns your Lovable repositories.

    Workflows do not run on a fresh fork until you allow them: open the Actions tab and enable workflows. Forks also do not inherit secrets, so you add your own in step 3.

  2. Create the Terraform state bucket (one time)

    S3 bucket names are global, so the default lovable-deployer-terraform-state is almost certainly taken. Pick your own name:

    cd terraform/bootstrap
terraform init
terraform apply -var="state_bucket_name=<your-unique-bucket-name>"

    This creates one bucket with versioning, AES256 encryption and all public access blocked. Keep the bootstrap's local state file and do not migrate it into the bucket it created.

    You do not need to create backend.tf or migrate state for the workflows; they generate backend.tf on every run.

  3. Add repository secrets

    In Settings, Secrets and variables, Actions, add the secrets you need. Minimum for Route 53: the two AWS keys, plus TERRAFORM_STATE_BUCKET if you did not use the default bucket name.

    gh secret set AWS_ACCESS_KEY_ID
gh secret set AWS_SECRET_ACCESS_KEY
# only if your state bucket name is not the default:
gh secret set TERRAFORM_STATE_BUCKET

    The gh commands are optional; the web UI does the same thing. For GoDaddy also add GODADDY_API_KEY and GODADDY_API_SECRET. The full list is in the secrets reference.

  4. Run the Deploy Lovable Website workflow

    Open Actions, Deploy Lovable Website, Run workflow and fill in the form (see the inputs reference):

    • repo_name: my-lovable-site
    • domain_name: example.com
    • subdomain: my-site
    • dns_provider: route53 (the form lists godaddy first, so check it)

    Or from the command line:

    gh workflow run deploy-lovable-website.yml \
  -f repo_name=my-lovable-site \
  -f domain_name=example.com \
  -f subdomain=my-site \
  -f dns_provider=route53

  5. Open your site

    The run summary ends with Website URL: https://my-site.example.com. A first deployment includes certificate validation and CloudFront propagation, so allow several minutes. The Terraform apply step has a 20 minute timeout. The CNAME has a TTL of 600 seconds, so DNS may take a little longer to be visible everywhere.

    Using GoDaddy?

    Expect the first run to need a manual certificate validation step and a second run. See the GoDaddy flow.

What happens on a first run#

  1. The workflow looks for the bucket <subdomain>.<domain_name> and a CloudFront distribution that uses it. Neither exists, so it runs the full flow.
  2. For Route 53 it looks up the hosted zone named domain_name.
  3. It writes terraform/backend.tf pointing at projects/<repo_name>/terraform.tfstate in your state bucket, then runs terraform init, refresh and apply.
  4. It checks out your Lovable repo, runs npm ci and npm run build, and finds the output directory.
  5. It runs aws s3 sync --delete into the bucket and invalidates /* in CloudFront.
  6. It creates the CNAME at your DNS provider and writes a summary.

Next steps#

  • Change code in the Lovable repo, then redeploy with the same inputs.
  • Understand what was created.
  • Something failed? Try troubleshooting.
