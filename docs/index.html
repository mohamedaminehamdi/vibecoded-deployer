GitHub Actions + Terraform + AWS

Put your Lovable app on your own domain, on AWS, from one form.

vibecoded-deployer is a control repository. Fill in a repo name, a domain and a subdomain. The workflow provisions S3, CloudFront and an ACM certificate with Terraform, points DNS at it, then builds and uploads your React app.

What you get

Everything below is what the workflows and Terraform in the repository actually do.

One form, one site

A workflow_dispatch form takes repo_name, domain_name, subdomain, dns_provider and an optional force_infrastructure flag.

HTTPS by default

An ACM certificate is requested for <subdomain>.<domain> and CloudFront redirects HTTP to HTTPS.

Your DNS provider

Route 53 is fully automatic. GoDaddy gets its CNAME through the API; certificate validation is a manual step.

Fast redeploys

If the bucket and the distribution already exist, Terraform is skipped. The run builds, uploads and invalidates the cache.

State per project

Each project keeps its own Terraform state in your S3 bucket under projects/<repo_name>/, with S3 native locking.

Guarded teardown

The destroy workflow only runs when you type DESTROY. It removes the AWS resources, the DNS record and the state file.

How it works

The workflow runs in your GitHub repository and creates resources in your AWS account. Nothing is hosted by anyone else.

Pick your DNS flow

Both end with a CNAME for <subdomain>.<domain> that points at CloudFront. The difference is certificate validation.

Automatic

Route 53

Terraform writes the validation records, waits for the certificate, and the workflow upserts the CNAME. One run.

 One manual step

GoDaddy

The CNAME is written through the GoDaddy API, but you add the certificate validation record yourself. Plan for two runs.

Good to know before you start

These are design choices, not bugs. Check that they fit your use case.

The bucket is public

Objects are world-readable and CloudFront reaches S3 over HTTP. Only deploy content that is meant to be public.

One deployment per repo name

The state key contains only repo_name. Do not deploy one repo to two subdomains.

Same GitHub owner

The Lovable repo must live under the same owner as your copy of this repository.

Fixed regions

S3 and state use us-west-2; the certificate uses us-east-1. Both are hard-coded.
